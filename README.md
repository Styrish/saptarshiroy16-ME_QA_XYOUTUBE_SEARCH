# YouTube Web Automation

A UI automation project built with **Java, Selenium WebDriver, TestNG, and Gradle** to test navigation and content checks on YouTube.

The project completed its platform assessment, and its source code is published on GitHub.

## Test scenarios

| Test | Scenario | Validation |
| --- | --- | --- |
| `testCase01` | Navigate to YouTube and open the About page | Read and print the About heading and page content |
| `testCase02` | Open Movies & TV and move through the Top selling carousel | Read movie metadata and check category and audience rating against the configured allowed values |
| `testCase03` | Open Music and read the selected playlist badge | Parse the track count and assert that it is **50 or fewer** |

The movie test uses the configured categories **Comedy, Animation, and Drama**, and audience labels **A, U/A 13+, and U/A 16+**. Review these expectations against the assignment and current content when maintaining the tests.

## Implementation highlights

- Reusable wrappers for navigation, clicks, waits, and text extraction.
- Explicit waits for dynamic page elements.
- Carousel interactions until the next arrow is unavailable.
- Selenium text reads for movie metadata and playlist counts.
- Assertions for the configured content requirements.
- ChromeDriver command logs for troubleshooting and platform assessment.

## Prerequisites

- JDK 17
- Google Chrome
- Git
- Internet access to YouTube and dependency repositories

Use the Gradle wrapper included in the repository; a separate Gradle installation is not required. ChromeDriver must be compatible with the installed Chrome version. Selenium Manager can resolve the driver when supported by the environment.

## Setup

1. Clone this repository using its GitHub clone URL.
2. Open the cloned project directory.
3. Confirm that `src/test/resources/testng.xml` selects `demo.TestCases`.
4. Ensure the intended tests are enabled before execution.

The assessed scenarios are `testCase01`, `testCase02`, and `testCase03`. Any additional unfinished or data-driven tests should be configured separately before enabling them.

## Run the tests

From Git Bash, macOS, or Linux:

```bash
./gradlew clean test --console=plain
```

From Windows PowerShell:

```powershell
.\gradlew.bat clean test --console=plain
```

To save console output in Git Bash:

```bash
./gradlew clean test --console=plain > test-run.txt 2>&1
```

To run tests and generate the Checkstyle report:

```bash
./gradlew clean test checkstyleTest --console=plain
```

## Reports and logs

After execution, inspect:

- **Test report:** `build/reports/tests/test/index.html`
- **Test result XML:** `build/test-results/test/`
- **ChromeDriver log:** `build/chromedriver.log`, when enabled in the driver setup
- **Checkstyle XML:** `build/reports/checkstyle/test.xml` when generated by the configured Checkstyle task

## Platform assessment

In the original assignment environment, run the provided assessment script after generating the test results and logs:

```bash
./run_platform_assessment.sh
```

The assessment checks code-quality requirements and recorded browser actions, including navigation, clicks, and text extraction. The project completed its platform assessment successfully. Assessment success and TestNG assertion results should both be reviewed when validating changes.

## Maintenance notes

YouTube is a live website. Navigation menus, page structure, movie metadata, and playlist counts can change by date, region, or session.

- Expand the sidebar when required to access Movies & TV or Music.
- Update locators when the page structure changes, especially selectors based on section position or CSS classes.
- Hidden carousel cards may not return visible text through `getText()`. Collect details while navigating if every card must be checked.
- A playlist with more than 50 tracks should fail the configured assertion; do not change the reported count to make the test pass.
- Use the test report and ChromeDriver log from the same run when investigating failures.
